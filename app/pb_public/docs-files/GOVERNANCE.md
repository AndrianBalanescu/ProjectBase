# Governance

ProjectBase is an MIT-licensed, community-contribution-friendly project currently maintained under a **benevolent maintainer** model.

## Decision making

The repository owner and designated maintainers have final responsibility for scope, releases, security responses, repository access, and merging changes. Decisions should favor the project's published purpose: a lean, self-hosted project tracker for humans and local agent execution, without commercial tiers or unnecessary platform expansion.

For routine changes, maintainers decide through issue and pull request review. Material changes to architecture, data compatibility, governance, or product scope should begin with a public issue so trade-offs can be discussed before implementation. Consensus is preferred, but it is not required when a decision is needed.

## Roles

- **Users** run the software and provide feedback.
- **Contributors** submit issues, documentation, designs, or code under the repository license.
- **Maintainers** review contributions, triage reports, manage releases, and enforce project policies.
- **Repository owner** appoints or removes maintainers and resolves decisions that remain contested.

There is currently no elected steering committee or formal voting process. Maintainer status is based on sustained, constructive contributions, sound judgment, respectful collaboration, and demonstrated care for the project's boundaries and users. Repository access may be reduced when inactive or when required to protect the project.

## Project boundaries

ProjectBase will remain free and open source under the MIT license. The project does not accept monetization, subscriptions, billing systems, paid tiers, or changes whose main purpose is unrelated feature expansion. Proposals should improve the core project-management, self-hosting, interoperability, accessibility, reliability, or local agent-execution experience without undermining the lightweight architecture.

Maintainers may decline well-implemented changes that increase maintenance burden, duplicate existing scope, or conflict with these boundaries.

## Transparency and changes

Technical decisions normally remain visible in issues and pull requests. Security handling and conduct reports may remain private. Governance changes are made through pull requests to this document and take effect when merged by the repository owner.
